# Nymphai Cosmetics — reconstruction

A static reconstruction of the **nymphaicosmetics.com** experience: the split-screen
hero, the percentage preloader, the scroll-pinned product showcase, the corner
navigation frame and the custom cursor — rebuilt from scratch as plain
HTML, CSS and JavaScript with **no dependencies and no build step**.

> **What this is.** A study of the layout, motion and information architecture of
> the reference site. It is not affiliated with Nymphai Cosmetics. All imagery is
> original vector artwork generated by `tools/generate-art.mjs`; no photography
> from the original site is reproduced. Company registration details in the
> footer are placeholders, and the checkout is not connected to anything.

---

## Running it

Any static server works. There is nothing to install or compile.

```bash
python3 -m http.server 8000
# or: npx serve .
```

Then open <http://localhost:8000>.

Opening `index.html` straight from the filesystem works too — the scripts are
classic `<script>` tags rather than ES modules, precisely so `file://` keeps
working.

Add `?intro` to the home page URL to replay the preloader
(`index.html?intro`); normally it runs once per browsing session.

## How the pieces work

**Preloader.** Tracks real `document.images` load progress, floored by a minimum
on-screen time so the meter never flashes past on a warm cache and capped so a
slow asset cannot trap the visitor. At 100% the centre card scales up and the
curtain fades. Shown once per session (`sessionStorage`), and skipped entirely
under `prefers-reduced-motion`.

**Hero.** Three slides, each split into two halves that wipe in from the centre
line with `clip-path`. The caption and title swap corners per slide
(`data-layout="a" | "b"`). The centre *Explore* card cycles through its images
and links to the current slide's product. Autoplay pauses when the tab is hidden.

**Pinned showcase.** The section is `(products + 1) × 100svh` tall with a
`position: sticky` stage. Scroll progress across the pin maps to a panel index,
which drives the panel crossfade, the `01 / 03` counter, the thumbnail rail and
the stage background colour. Panels are rendered from `data.js`, so they follow
the catalogue and the language switch.

**Inertial scrolling.** `motion.js` intercepts wheel events and eases the *real*
document scroll position, rather than transforming a wrapper element. That keeps
`position: sticky`, anchor links, find-in-page and the native scrollbar working.
It is disabled on touch devices (native momentum is better) and under reduced
motion.

**Chrome inversion.** Sections declare `data-chrome="light"` when dark media sits
behind the fixed frame. Whichever section owns the vertical centre of the
viewport sets `data-chrome` on `<html>`, and the frame, cursor and scroll rail
recolour from one custom property.

**One ticker.** Every scroll-linked module subscribes to the single
`requestAnimationFrame` loop in `core.js` instead of starting its own.

## Editing the content

Products live in `assets/js/data.js`. Each entry carries the stable, shared
fields (id, price, volume, image paths, accent colours) plus an `it` and an `en`
block for everything that gets translated. Adding a product to that array adds it
to the catalogue, the home line-up, the pinned showcase and the cart.

Interface copy lives in `assets/js/i18n.js`. Markup opts in with
`data-i18n="key"`, or `data-i18n-attr="placeholder:key"` for attributes. The two
dictionaries are intended to stay key-for-key identical.

Design tokens live in `assets/css/tokens.css` — palette, type scale, spacing,
radii and easing. Changing the brand colours is a single-file edit.

## Replacing the artwork

Every image is a generated SVG placeholder in the brand palette. To use real
photography, drop `.webp` or `.jpg` files into `assets/img/` and update the paths
in `assets/js/data.js` (products) and in `index.html` / `brand.html` (hero and
editorial slots). Nothing else needs to change — the CSS sizes everything with
`object-fit`.

To regenerate or restyle the placeholders:

```bash
node tools/generate-art.mjs
```

The generator is deterministic (seeded randomness), so re-running it produces no
spurious diff.

## Browser support and accessibility

Current Chrome, Firefox, Safari and Edge. The layout was verified from 360 px to
2560 px wide, including short viewports where the pinned showcase drops its body
copy rather than spilling under the fixed frame.

- Every page has one `<h1>`, a skip link and a `<main id="main">`.
- The custom cursor is decorative; it is hidden on touch and under reduced
  motion, and the real pointer is never suppressed.
- `prefers-reduced-motion: reduce` disables the preloader, the inertial scroll
  and every transition; content renders in its final state.
- `localStorage` and `sessionStorage` access is wrapped in `try/catch`, so
  private-browsing and blocked-cookie contexts degrade to "nothing was stored"
  instead of throwing.

## Deploying

`.github/workflows/deploy-pages.yml` publishes the repository root to GitHub
Pages on every push to the repository's **default branch**, after checking that
the committed artwork still matches the generator. Enable it under
**Settings → Pages → Source: GitHub Actions**. `.nojekyll` is present so Jekyll
does not filter any paths.

The workflow deliberately keys off `github.event.repository.default_branch`
rather than a hard-coded branch name, so it works whether the default ends up
being `main`, `master`, or the branch this was first pushed to.
